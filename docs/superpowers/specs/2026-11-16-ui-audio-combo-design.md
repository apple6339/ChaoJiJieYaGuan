# 界面动效、声音与轻量连击设计

状态：待书面审阅。本文只定义设计。审阅通过之前，不写实现计划，不改游戏代码。

本阶段没有运行游戏，也没有重新构建。文中「仓库事实」来自已审查的源码与资源；「建议设计值」是本规格选定的参数，不是现有代码里的数字。

## 1. 目标与非目标

玩家仍按原规则合成。这一版只让操作更清楚、反馈更明确，并用连击分数增加重复合成的节奏。连击不改变发出的硬币、合成出的硬币、槽位或关卡目标。

不做广告、付费、登录、分享、排行榜和侧边栏。不下载、不购买、不生成新图片或来源不明的音乐。

## 2. 已选方案

比较过三种做法：

1. 连击只累计分数和表现。合成、发牌、槽位、关卡公式保持原样。推荐此方案，改动落在现有按钮、音效和一次点击的锁上。
2. 连击改变发牌权重或合成枚数。否决。这会改变对局结果。
3. 连击写入排行榜或最佳成绩。否决。当前没有账号和排行实现，本版不扩大存档。

## 3. 必须守住的仓库事实

以下行为本版不改。

- 一槽容量 10。只有该槽 10 枚且顶部连续 10 枚同号才可合成。合成结果仍由现有 `CountsWeight` 决定，号码加 1。
- 发牌仍用现有 `CountsWeight` 与 `TypesWeight`。空的 `arr5` 保持不动，因为当前进度索引只用 0 到 4。
- 12 槽及解锁顺序不变：0–4 普通，5 下次可解锁，6–8 锁定，9–11 临时槽。临时槽仍点按直接解锁，不接广告。
- 关卡目标仍按 `level * 6 - 1` 生成 5、6、7、9、10 这一档的现有跨度。过关条件仍是场上出现当前最高目标号。
- 设计分辨率保持 750×1334，只按宽度适配。
- 旧存档键的含义不变，见第 8 节。
- 引导步骤的顺序和完成条件不变。引导未完成时不记连击、不加分。
- 隐藏的测试按钮保持关闭。不启用全屏 `OverMask`。

## 4. 界面

用现有金币、棕色面板和蓝色按钮，不新增图片。文案使用已有的系统字体 Label，与「第 N 关」相同。本版固定使用这些中文，不使用英文标点和字母做主要文案：

| 位置 | 文案 |
| --- | --- |
| 原排行榜按钮处 | 得分 |
| 底部按钮上方，仅连击数大于等于 2 时 | 连击 2 |
| 过关短时提示 | 过关 |
| 设置里新增的两行 | 操作音、反馈音 |

原排行榜按钮目前可点，但处理函数为空。本版去掉它的按钮组件，节点改为不可点的得分显示，避免点了没有反应。继续使用现有排行图标，旁边用 Label 显示整数，不换图。

层级：

- 背景继续铺满屏幕，可以伸进刘海外。
- 关卡文字、得分、设置按钮、底部三个操作按钮放进同一个 HUD。洗牌按钮仍只在原条件出现。
- HUD 使用 Widget，并加上引擎 SafeArea。安全区不可用时边距为 0，不自行猜测刘海高度。内缩后若底部按钮与棋盘重叠，只上移按钮，不缩小槽位，也不改 12 槽布局。
- 棋盘仍在背景和底部按钮之间，不改槽的 Grid 尺寸。设置里的「操作音」「反馈音」放在现有音效开关下面，复用现有开关尺寸。面板空间不够时只减小行距，不新增面板图。
- 连击文字和「过关」不是按钮，不拦截棋盘点击。「过关」出现时由输入锁挡住操作，而不是靠全屏遮罩。

动效只做短、稳的反馈，禁止整屏闪白、透明度来回闪和摄像机震动。硬币放不下时现有的左右轻晃保留，它只晃硬币，不晃屏幕。

| 反馈 | 做法 | 建议设计值 |
| --- | --- | --- |
| 按钮按下 | 在现有缩放上按下后弹回。禁用态继续用现有灰度，不改成闪烁 | 缩到 0.96，去程 80 毫秒，回程 80 毫秒 |
| 槽选中 | 保留现有硬币抬起。选中时把该槽 `CellBg` 设为暖色，结束时恢复选中前的颜色。不播放 `CellFocus`，该动画时长为 0 且没有曲线 | RGB(255, 236, 196)，不循环、不闪 |
| 合成 | 保留 `Cell.mergeCoin` 里已有的缩放轻弹，不另加一套缩放 | 不新增时长 |
| 粒子 | 使用槽上已有的粒子组件和已有 `Light1` 贴图，爆发一次 | 8 颗，寿命 0.35 秒，不循环 |
| 过关 | 显示「过关」，然后走现有的下一关重置 | 显示 800 毫秒 |
| 震动 | 玩家的震动开关仍有效。普通合成用一次短震。造成过关的那次合成只做一次长震，不再叠加短震 | 连击不额外加震 |

粒子资源 uuid `e17b4526-57a2-48d3-acc9-cf09f30aa138` 在仓库中没有对应文件。实现时不得再依赖这个丢失文件。贴图缺失或组件报错时关掉粒子，合成和得分照常完成。

## 5. 声音

### 5.1 授权

仓库音效可在本地自测中复用。README 指向的课程素材没有商用授权文件，MIT 不覆盖这些声音。本规格允许自测使用现有文件，不承诺可以商用，也不用新的不明来源音乐或音效替换它们。

### 5.2 复用哪些文件

下列对应关系是仓库事实。`AudioName` 里的 12 个名字都能找到文件。

| 现有用途 | 文件 | 本版 |
| --- | --- | --- |
| 发牌 | `giveCoin` | 每次发牌手势播 1 次 |
| 重开发牌 | `resetStart` | 保持 |
| 拿起 | `chooseCoin` | 保持 |
| 落下 | `placeCoin` | 改为每次移动手势播 1 次。现在是每枚硬币播 1 次 |
| 放不下、点锁定槽 | `warn` | 保持 |
| 新出现可合成 | `tz_full` | 保持现有「这一次检查只播一次」 |
| 合成 | `merge` | 普通合成播 1 次。造成过关时不播 |
| 解锁完成 | `getArea` | 保持 |
| 槽变为可解锁 | `unlockArea` | 保持 |
| 开关点击 | `click` | 保持，走界面层 |
| 打开和关闭设置 | `btn` | 保持，走界面层 |
| 洗牌 | `shuffle` | 保持 |
| 当前没有播放 | `merge10` | 仅在连击大于等于 2 且这次没有过关时加播 1 次 |
| 当前没有播放 | `win` | 仅过关时播 1 次 |
| 当前没有播放 | `error`、`renewArea`、`tz_giveCoin` | 继续不播。`tz_giveCoin` 与 `giveCoin` 内容重复 |

不把整个 `sound` 目录都播出来。启动时仍可加载目录，但播放入口只接受上表允许的名字。

### 5.3 分层、音量与开关

三层独立输出，避免界面点击、落子和过关叠在一起时互相盖住。

| 层 | 内容 | 建议增益 | 开关 |
| --- | --- | --- | --- |
| 界面 | `click`、`btn` | 0.85 | 只跟随总开关 |
| 操作 | 拿起、落下、发牌、重开、洗牌、警告 | 0.70 | 总开关，以及新的操作音开关 |
| 反馈 | 可合成、合成、`merge10`、过关、解锁 | 1.00 | 总开关，以及新的反馈音开关 |

三层仍共用现有的一个 `AudioSource`。总开关打开时节点音量为 1，每层用 `playOneShot` 的音量系数区分响度。不新建音频节点。

总开关继续使用设置里现有的音效开关。它写入旧键的方式不变：开为 1，关为 0。总开关关闭时三层都不播。

操作音和反馈音是两个新开关，界面用现有的开/关按钮图，文字用系统字体。不新增滑条。层的响度只用上表增益，不把总音量改成小数。这样旧存档里的 `volume` 不会被解释成另一套含义。

同一文件的播放间隔至少 80 毫秒。一次玩家操作里，同一文件最多播 1 次。过关时只播 `win`，不叠加 `merge` 和 `merge10`。

### 5.4 后台

游戏进入后台时停止当前播放，并丢掉后台期间新来的播放请求。回到前台后，只有总开关仍为开时才恢复播放能力。不自动补播，也不新增背景音乐。现有音效节点可以继续常驻，但必须接上隐藏和显示。

## 6. 连击与得分

连击和得分只存在于内存中的一个模块。它不修改硬币、槽和关卡。

### 6.1 什么算一次成功

玩家主动按下合成，并且这次至少合成成功 1 个槽，记为 1 次成功。同一次点击里合成多个槽，连击只加 1，不多加。槽数只影响分数。

引导未完成时不调用记分。合成 0 个槽不改变连击和分数。

### 6.2 时窗、重置与封顶

建议设计值：时窗 8000 毫秒，连击封顶 8。计时用真实时间。打开设置或切到后台都不暂停时钟。

一次成功后，连击变为 `min(8, 当前连击 + 1)`，并把时窗终点改成这次成功的时间加 8000 毫秒。界面每 200 毫秒检查一次超时。超过终点后连击回到 0，文字隐藏。此后第一次成功从 1 开始。这 200 毫秒只影响文字何时消失，不改变 8000 毫秒的时窗。

不打断连击、也不刷新时窗的操作：选中、放下、移动、移动失败、发牌、解锁、开关设置、调节声音或震动。

立即把连击回到 0 的操作：

| 原因 | 时机 |
| --- | --- |
| 超时 | 到达时窗终点 |
| 重开 | 设置里的重开，在重新发牌之前 |
| 洗牌 | 洗牌动画开始之前 |
| 切关 | 造成过关的那次合成已经计分之后、进入下一关重置之前 |

### 6.3 计分公式

建议设计值，全部是整数：

```text
本次得分 = 100 × 本次合成槽数 × 计分后的连击数
本局分数 = min(999999, 本局分数 + 本次得分)
```

例：第一次成功合成 1 槽得 100。8 秒内又成功合成 1 槽，连击为 2，得 200。一次点击合成 2 槽且连击已到封顶 8，得 1600。

本局分数跨自然过关继续累加。重开时本局分数和连击一起归零。洗牌和超时只清连击，不清本局分数。进程结束后分数消失。

界面只在连击大于等于 2 时显示「连击 N」，N 为封顶后的整数。得分始终显示「得分」加当前本局分数。不使用货币符号。

### 6.4 和过关的顺序

引导未完成时，不显示「过关」，不额外等待，不计分，也不改连击。过关若在引导中发生，仍立即执行现有重置，避免打断引导步骤。

引导完成后的顺序是：

1. 按原规则完成合成。
2. 槽数大于 0 时先记连击和分数。
3. 播放对应声音和轻弹。粒子失败不影响第 2 步。
4. 若这次合成达到过关条件，锁定输入，显示「过关」并只播 `win`，等待 800 毫秒。
5. 将连击归零，再执行现有的关卡加一和棋盘重置。本局分数保留。

## 7. 职责与数据流

四个单元各自只做一件事。现有 `MdGame` 继续当流程入口，只在原有成功、重开、洗牌和过关点上调用它们，不把规则搬进界面节点。

### ComboTracker

内存模块。负责时窗、封顶、分数和重置原因。

- `recordSuccess(columnCount, nowMs)`：槽数小于 1 时返回空，不改变状态。否则返回本次连击、本次得分和本局分数。
- `expireIfNeeded(nowMs)`：超时则归零。
- `reset(reason)`：`reason` 只能是 `timeout`、`restart`、`level`、`shuffle`。重开同时把本局分数归零，其余原因只清连击。
- `getState()`：返回连击、本局分数和时窗终点。

它不播放声音，不改节点，不读存档。

### FeedbackPlayer

只负责看得见的反馈。

- `playButtonPress(node)`
- `playSlotHighlight(cell, on)`：稳定高亮，不做循环。
- `playMergeParticle(cell)`：失败时静默跳过。
- `playCombo(combo)`：小于 2 时隐藏。
- `playLevelClear()`：显示「过关」，在建议的 800 毫秒后结束。
- `playScore(runScore)`

缩放轻弹仍留在现有 `Cell.mergeCoin`，这里不重复做。

### AudioBus

在现有 `AudioManager` 上小改，不另起一套音频引擎。

- `play(layer, name)`：总开关或该层开关关闭、处于后台、名字不在允许表、距离上次同一文件不足 80 毫秒时，直接返回。
- `setMasterEnabled(on)`：仍把旧键写成 1 或 0。
- `setLayerEnabled(layer, on)`：只接受操作层和反馈层。
- `suspend()` 与 `resume()`：处理后台。

文件缺失时保持现有行为：不播，不抛错，游戏继续。

### InputGuard

保留现有 `_globalLock` 计数，不新做一套输入系统。每次异步操作在第一个 `await` 之前加 1，并在 `finally` 里减 1。锁大于 0 时，发牌、合成、洗牌、移动、解锁、设置和重开都直接返回。

现有的锁还没有包住解锁动画。本版把解锁动画也放进同一把锁。过关的 800 毫秒同样持有这把锁。引导自己的遮罩和步骤保持原样，不把引导点击算进连击。

## 8. 存档边界

已有键只按原含义读写：

| 键 | 保持的含义 |
| --- | --- |
| `level` | 当前关卡，从 1 起 |
| `volume` | 总声音开关，1 为开，0 为关 |
| `vibrate` | 震动开关，1 为开，0 为关 |
| `guide` | 引导是否完成，1 为完成 |
| `cellData` | 继续保留现有读写函数，但本版不写入棋盘，也不把分数放进这个键 |

新键只有两个，旧存档没有它们时视为 1，也就是两层都开：

| 键 | 含义 |
| --- | --- |
| `sfxAction` | 操作音开关，1 或 0 |
| `sfxReward` | 反馈音开关，1 或 0 |

不把分数、连击或时窗写入本地存储。不迁移、不重写旧键。读到旧键的非数字内容时，继续用现有默认值，不因此清空关卡。

## 9. 错误降级

| 情况 | 结果 |
| --- | --- |
| 粒子贴图或组件不可用 | 跳过粒子，合成、得分和声音继续 |
| `win` 或 `merge10` 未加载 | 过关文字或连击文字仍出现，只是少这一声 |
| 安全区接口不可用 | HUD 边距为 0，布局退回现在的全屏拉伸 |
| 连击模块收到非法槽数或时间倒退 | 忽略这次记分，不把连击改成负数 |
| 后台期间触发播放 | 丢弃这次播放 |
| 动画中途抛错 | `finally` 释放输入锁，避免棋盘永久点不了 |

## 10. 验收与回归

验收只覆盖本规格。下列建议值用于断言：时窗 8000 毫秒，封顶 8，单槽基础 100 分，过关提示 800 毫秒，同一音效间隔 80 毫秒。

- 10 枚同号才合成；合成枚数和号码仍来自原权重。连击前后各做一次同样的合成，硬币结果一致。
- 发牌权重函数、12 槽解锁条件和关卡目标号码不改。
- 一次点击合成 2 槽，连击只加 1，分数按槽数乘连击。
- 8 秒内的移动和发牌不重置连击，也不刷新时窗。
- 超过 8 秒、重开、洗牌、过关都会把连击归零。过关那一次本身已经计分。
- 重开使本局分数归零。自然进入下一关后分数还在。重启进程后关卡还在，分数不在。
- 旧存档中的关卡、总声音、震动和引导完成状态读出来与改动前一致。总声音为 0 时三层都不播。
- 动画和过关提示期间连点发牌、合成、洗牌、设置，只有第一次进入的操作生效。
- 排行榜位置不可点击。测试按钮仍然关闭。没有广告和付费入口。
- 进入后台后声音停止，回前台不自动补播。工程里没有新增音乐文件。
- 粒子被故意禁用时，合成仍能完成并加分。

回归：引导 11 步仍能完成并写入 `guide`。设置里的原开关仍能保存。重开仍会重新发牌。临时槽仍可直接解锁。原有警告、拿起和洗牌声音仍能按开关播放。

## 11. 改动边界

允许的小改：扩展现有音频管理器、在现有流程入口调用连击和反馈、把移动音从每枚硬币收成一次手势、用 SafeArea 包住 HUD、把排行榜节点改成不可点的得分、设置面板复用现有开关图增加两行。

不允许：重写槽位或合成、调整权重和容量、新增广告或支付、新增图片和音乐、把分数写入旧键、顺手重构没有参与这些反馈的管理器。

## 12. 本机事实

以下内容由用户提供，只作为设计约束，不是本阶段的运行结果。

- 合法测试号是 `testAppId`。本规格不改 AppID，也不要求重新下载编辑器。
- 用户机器上的 Creator 3.8.5 已经构建出约 6.96MB 的包。本版不新增二进制资源，避免把体积问题重新引入设计。
- 后来出现的 `__MACOSX` 曾造成 IDE 编译错误，并已获准移出备份。本规格不触碰用户电脑上的暂存工程、备份或元数据。
- 原版在模拟器里是否可玩，还没有用户反馈。本文不把可玩当成已验证结论。

## 13. 自审

已通读本文，没有待定项、占位段落或未选定的参数。

- 范围能放进后续一份实现计划。计划本身不在本文。
- 「独立音量」落实为同一个 `AudioSource` 上的三层增益，加总开关、操作音开关和反馈音开关，没有做成滑条。这是为了不新增控件，也不把旧的 `volume` 从开关改成小数。
- 选中高亮固定改 `CellBg` 颜色，不用空的 `CellFocus`。连击文字每 200 毫秒检查超时，时窗仍是 8000 毫秒。
- 引导未完成时不插入过关停顿，避免和现有引导步骤抢时间。
- 发牌不重置连击。这是明确选择。若发牌也重置，正常对局几乎连不出第二次合成。
- 一次点击里的多个槽只加 1 次连击，槽数进入分数。这避免同一次点击被计成多次连击。
- 过关那次先计分再清连击。本局分数跨关保留，重开才清分。
